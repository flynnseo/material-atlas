`_inbox/` 의 메모를 수거한다. (README.md, done/ 은 건너뜀. "$ARGUMENTS" 가 있으면 이름에 그게 들어간 파일만.)

1. **묶기**: 확장자만 다른 같은 이름 파일(`x.md` + `x.jpg`)은 한 묶음. 사진만 있으면 사진을 Read 로 보고 무엇인지 한 줄로 파악(내용 판단용일 뿐, 카드엔 사진 링크만).
2. **카드 찾기**: 메모에서 소재·마감·브랜드·공간 이름, 은어, 규격번호를 뽑아 `node -e` 로 `scripts/search.js` 검색(site/index.json 없으면 먼저 `python3 scripts/build.py`)하고, 상위 결과를 직접 읽어 정말 그 얘기인지 확인한다.
   - 한 메모가 여러 카드에 해당하면 각 카드에 붙인다.
   - 맞는 카드가 없으면 붙이지 말고 `_meta/backlog.md` 해당 소재군에 `- [ ] 이름 | 소재군 | _inbox 메모 <파일명>` 추가.
   - 애매하면(후보 2개 이상, 확신 낮음) 붙이지 말고 리포트에 "확인 필요" 로 남기고 파일은 _inbox 에 둔다.
3. **붙이기**: 카드 본문 맨 아래 `## 태건 메모` 섹션(없으면 만든다)에 다음 형식으로 **원문 그대로**(오타·말투 수정 금지, 요약 금지):
   ```
   ### <YYYY-MM-DD> · <원본 파일명>
   <메모 원문>
   ![](../../assets/inbox/<사진파일명>)   ← 사진이 있으면 assets/inbox/ 로 옮기고 링크 (finishes/·cases/ 카드는 ../assets/…)
   ```
   날짜는 메모 안에 날짜가 있으면 그것, 없으면 파일 수정일.
   프론트매터·다른 섹션·수치는 건드리지 않는다. `updated` 만 오늘로.
4. **hands_on 후보**: 메모에 직접 해본 정황("해봤", "잘라봄", "붙였더니", "샘플 받아", 공정 파라미터, 실패담, 작업 사진)이 있으면 리포트에만 적는다. **hands_on 값은 절대 바꾸지 않는다**(태건만 승격).
   실험 성격이 강하면 "LAB 카드로 옮길 만함" 표시.
5. **이동**: 처리 끝난 묶음은 `_inbox/done/<YYYY-MM-DD>/` 로 `git mv` 가 아니라 일반 mv (아직 커밋 전일 수 있음).
6. `python3 scripts/build.py --test` → 오류 0 확인.
7. 리포트 표: `메모 파일 | 붙인 카드 | hands_on 후보(근거 한 구절) | 확인 필요/백로그 추가`. 커밋은 `/build` 로.
